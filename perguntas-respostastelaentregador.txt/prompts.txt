Instruções Estritas:

Estamos em modo produção: não inclua comentários no código, console.logs ou mock data visível em produção, exceto onde explicitamente permitido para logs de auditoria FSM.

Siga a arquitetura de camadas (Layered UI Architecture):

Layer 0 (Z-10): Header Vitals – status, bateria, sinal, FSM. pointer-events-none exceto nos elementos interativos internos.

Layer 1 (Z-20): Financial HUD – ganhos, metas, ranking, modo stealth. Wrapper pointer-events-none.

Layer 2 (Z-0): Canvas – views de Idle, En Route, POD. Scrollable area, animações com Framer Motion.

Layer 3 (Z-40): Control Deck – botões de ação, batching de missões, lock de movimento.

Layer 4 (Z-50): Motion Lock Overlay – bloqueio de interações ao dirigir acima de threshold, botão de emergência sempre acessível.

Layer 5 (Z-9999): Modais críticos – IncidentModal e quaisquer modais futuros.

FSM (DriverStateMachine):

Use transições otimizadas (Optimistic UI).

Bloqueie ações em conflito com Motion Lock.

Registre logs forenses via driverFSM sem expor dados sensíveis na UI.

Telemetria:

Use useDriverTelemetry com batching de 5 pontos.

Ajuste zoom de forma logarítmica conforme velocidade.

Inclua cálculo de CTE ou desvio de rota (simulado ou real via turf).

Feedback:

Use SensoryEngine para vibração, áudio e notificações de sucesso/erro.

Toasts devem ser concisos e contextuais, integrados com o estado FSM.

Modais:

Bloqueio de ESC ativo para IncidentModal.

Botões de fechamento/cancelamento claros para não frustrar o usuário.

Z-index máximo (9999) para sobreposição crítica.

UI/UX:

As transições de views devem usar AnimatePresence e motion do Framer Motion.

Respeite a hierarquia visual e pointer-events para prevenir ghost clicks.

Layout responsivo: HUD e Vitals devem funcionar em todos os dispositivos da frota.

Produção:

Remova todos os console.log, comentários e dados de mock não essenciais.

Certifique-se de que todos os hooks, FSM e telemetria funcionem com dados reais simulados para produção.

Componentização e organização:

Crie subcomponentes apenas quando necessário para manter o DriverCockpitPage limpo.

Toda lógica de side-effects e hooks deve ser encapsulada corretamente.

Componentes auxiliares como EnRouteView, PodView e IdleView devem ser integrados sem quebrar o layout em camadas.

Entrega:

Gere apenas o código final pronto para produção, sem placeholders ou comentários.

Use tipagem TypeScript rigorosa sempre que possível.

Certifique-se de que todos os estados FSM, batch de missões, motion lock e incident modal funcionem perfeitamente em conjunto.

Mantenha a hierarquia de camadas (Layered UI Architecture) e Z-index exato.

Objetivo Final:
Criar uma versão completa e pronta para produção do DriverCockpitPage que funcione como dashboard operacional para entregadores, seguindo o protocolo da documentação, integrando FSM, telemetria, feedback sensorial, modais críticos e layout de camadas.
